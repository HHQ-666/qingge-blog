# 宠物运行可靠性修复实施计划

**目标：** 修复宠物模型加载卡住、切换失败后状态不一致、切换预加载过重以及仙狐显示比例不合适的问题。

**方案：** 在 `PetCompanion.svelte` 内增加可取消的模型加载超时与明确失败状态；切换成功后再提交当前索引，失败时真实切回原模型；预加载只请求模型配置、核心资源和已配置动作，避免一次性抓取全部动作；在 `manifest.json` 中微调仙狐比例。保持现有右键菜单和紧凑 UI，不新增独立面板。

**验证：** `pnpm check`、`pnpm test`、`pnpm build`、`git diff --check`，并使用本地生产预览确认失败时不会无限显示“正在准备”。

## Task 1：为加载失败增加边界

**文件：** `src/components/fun/PetCompanion.svelte`

- 增加统一超时常量、计时器清理函数和模型加载错误状态。
- 初始加载和切换加载最多等待固定时间；超时后显示可理解的失败提示并恢复可交互状态。
- 失败状态允许用户再次右键菜单选择其他形象，不让组件永久停留在 loading。

## Task 2：修复切换状态与真实回滚

**文件：** `src/components/fun/PetCompanion.svelte`

- 切换过程中使用独立的目标索引，成功收到 `loaded` 且动作可用后再更新 `currentIdx`。
- 失败时调用组件实际的旧模型索引恢复，而不是只修改 UI 索引。
- 防止快速连续点击造成并发切换，上一轮切换结束前忽略新的切换请求。

## Task 3：减轻模型预加载

**文件：** `src/components/fun/PetCompanion.svelte`

- 保留模型配置和基础资源预热。
- 只预加载 manifest 中配置的动作文件，不遍历模型配置里的全部动作和表情。
- 复用进行中的预加载 Promise，避免 hover、touch 和 click 重复发起请求。

## Task 4：调整仙狐比例并验证

**文件：** `public/pets/manifest.json`

- 将仙狐比例从当前明显过小的值调整到可观察的初始值。
- 通过生产构建和浏览器预览确认模型不会被缩成碎片；如果远程 CDN 仍不可用，至少能明确显示加载失败而非无限等待。
