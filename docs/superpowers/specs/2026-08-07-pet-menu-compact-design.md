# 桌面宠物极简右键菜单设计

## 背景

当前宠物右键菜单使用较大的形象卡片和独立“互动”区域，占用空间明显。部分互动项实际只是显示预设气泡，尤其“聊天”不是对话功能，容易让用户误以为点击后会发生更多事情。黑猫和白猫也没有可用的动作配置，因此显示通用互动按钮时体验不一致。

## 目标

- 将右键菜单压缩为适合桌面常驻的轻量菜单。
- 让五个宠物缩略图在小尺寸下仍能识别，并更新狐娘、白猫、黑猫的缩略图。
- 移除只有文字反馈的“聊天”入口。
- 只展示当前模型实际存在的动作能力。
- 去掉 l2d-widget 自带的左侧竖向加载条，改为紧贴宠物的小型横向加载/切换提示。

## 方案

### 菜单布局

- 使用极简模式，菜单宽度约 248px，并限制最大高度。
- 顶部显示当前宠物名称和一个“隐藏”图标按钮。
- 五个宠物采用横向可滚动缩略图条，每项只包含小头像和短名称；当前项使用边框和勾选标记强调。
- 不再显示“互动”标题或空白互动面板。
- 当前宠物拥有可用动作时，底部仅显示一个紧凑的“动作”按钮，点击播放该宠物的主要卖萌动作；没有动作时不显示该按钮。
- “随机动作”不作为常驻按钮，仅在当前模型存在多个非待机动作时并入动作入口或作为次级操作。

### 功能边界

- 形象切换：保留现有模型切换逻辑和右键/长按触发方式。
- 动作：继续调用模型真实的 `.mtn` 或 `.motion3.json` 动作文件；气泡只作为辅助提示，不作为功能本身。
- 聊天：移除 `sayRandom` 菜单入口，保留动作产生的短提示气泡。
- 隐藏：保留 `widget.sleep()`，放在菜单顶部作为系统操作。
- 黑猫、白猫：因当前没有动作配置，只显示形象切换和隐藏，不显示伪互动按钮。

### 加载状态

- 将 `statusBar` 设为关闭，避免库的左侧竖向“正在加载”条。
- 在组件内维护初始化和切换状态，在宠物附近显示小型横向胶囊提示，例如“正在准备”和“切换中”。
- 加载完成后自动隐藏提示；失败时使用已有气泡反馈，不额外占用菜单空间。

### 缩略图

- 统一使用透明背景、同一视觉裁切比例的 WebP 缩略图。
- 使用对应 Live2D 模型的清晰正面或半身帧生成 `senko.webp`、`tororo.webp`、`hijiki.webp`，替换现有 SVG 占位插画。
- 保留 manifest 中的 `avatar` 字段，组件不增加额外的模型识别逻辑。

## 验证

- 菜单在桌面和窄屏下不遮挡大面积内容，缩略图可横向滚动。
- 五个缩略图均能正确加载，当前项状态明确。
- 有动作的模型点击“动作”时会播放真实动作；无动作模型不显示动作入口。
- “聊天”不再出现在菜单中。
- 初始化和切换时不再出现左侧竖向加载条。
- 运行 `pnpm check`、`pnpm test` 和 `pnpm build`，并在浏览器中进行一次右键菜单和模型切换视觉检查。
