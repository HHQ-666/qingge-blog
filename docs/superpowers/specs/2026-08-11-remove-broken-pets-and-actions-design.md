# 移除异常宠物模型与底部互动按钮设计

> 日期：2026-08-11
> 状态：已确认，待实施
> 范围：宠物模型清单与紧凑右键菜单

## 1. 背景与目标

“日和”和“Haru 接待版”使用的全身 Live2D 资源在当前固定舞台与紧凑菜单中无法稳定呈现：头像缩略图过窄，移动端实际模型也会遮挡页面内容。用户决定暂不展示这两个模型；菜单底部的“问候/回应/开心/休息”等互动按钮也不再保留。

目标：

- 宠物菜单只展示当前可正常使用的四个模型：Pio、静香、小春、Haru。
- 移除菜单底部互动按钮区域，减少无实际价值的操作入口。
- 保留被移除模型的本地资源文件，便于将来重新适配后恢复。
- 不影响剩余模型的加载、切换、隐藏、气泡与点击互动能力。

## 2. 方案与范围

### 2.1 模型清单

从 `public/pets/manifest.json` 移除 `hiyori` 与 `haru-greeter` 两个条目。只删除 manifest 入口，不删除：

- `public/pets/models/hiyori/`
- `public/pets/models/haru-greeter/`
- 对应头像文件

这样可以避免无效资源继续被运行时初始化，同时保留未来重新接入所需的完整文件。

### 2.2 菜单互动区

从 `src/components/fun/PetCompanion.svelte` 移除模型菜单底部的 `pet-action-strip` 与 `pet-primary-action` 渲染和对应样式。模型切换菜单、关闭/隐藏入口、加载失败入口保持不变。

动作映射数据暂时保留，因为模型点击事件仍可调用 `playCuteAction`；本次只删除用户明确指出的菜单按钮，不扩大为删除所有动作资源与交互逻辑。

### 2.3 测试同步

更新 `scripts/test/pet-manifest.test.mjs`：

- 期望模型顺序调整为 `pio`、`shizuku`、`koharu`、`haru`。
- 本地模型资源图只校验 `koharu` 与 `haru`。
- 增加断言，确保 `hiyori` 与 `haru-greeter` 不再出现在 manifest 中。
- 不断言对应资源文件被删除，因为资源保留是本次设计的一部分。

## 3. 数据流与行为

1. 组件加载 manifest。
2. 过滤后的四个模型传入 `l2d-widget`。
3. 右键菜单根据四个 manifest 条目生成头像入口。
4. 菜单只显示模型切换区，不再渲染底部互动按钮区。
5. 点击剩余模型时沿用现有切换、预加载、失败回滚和加载超时逻辑。

## 4. 错误处理与兼容性

- 若 manifest 中模型数量减少，默认模型索引仍通过 `defaultPet` 按 id 查找，不依赖固定数字索引。
- 移除模型后，剩余模型的动作映射与加载资源图继续由现有测试校验。
- 旧模型资源未被引用，不会产生网络请求。
- 不修改第三方 `l2d-widget` 包，也不改变页面其他组件。

## 5. 验证标准

- 菜单中只出现 Pio、静香、小春、Haru 四个模型。
- 菜单底部不出现“问候/回应/开心/休息”等互动按钮。
- 剩余模型可正常加载和切换，点击模型仍不报错。
- `pnpm check`、`pnpm test`、`pnpm build`、`git diff --check` 全部通过。
- 生产构建输出不再引用被移除模型的 manifest 入口。

## 6. 非目标

- 不删除两个异常模型的磁盘资源。
- 不重绘头像、不调整 Live2D 舞台尺寸。
- 不删除模型动作文件或模型点击互动的底层实现。
