# Live2D 宠物迁移与右键互动设计

> 日期：2026-08-07
> 状态：已确认方向，待 spec review
> 关联项目：清哥的小屋（Astro 5 + Svelte）

## 1. 背景与目标

当前博客使用 `oh-my-live2d@0.19.3` 加载 Live2D 宠物，并在 `PetCompanion.svelte` 中包了一层右键菜单。现有交互入口已经统一，但仍有三个问题：

- 组件依赖旧版 API，模型切换、隐藏和气泡调用与新版运行库不一致；
- Pio、静香两个少女模型使用手绘 SVG 作为缩略图，和真实模型外观不一致；
- 菜单里的互动主要是聊天气泡，模型自带动作没有被利用，体验显得单调。

本次目标：

1. 将运行库从 `oh-my-live2d` 迁移到其后续重构版本 `l2d-widget`；
2. 保留并强化“右键宠物打开唯一功能菜单”的交互；
3. 使用真实 Live2D 模型渲染出的预览图替换少女缩略图；
4. 将模型动作和表情接入菜单，支持卖萌、撒娇、跳舞/唱歌、睡觉和随机动作；
5. 保证 Astro 页面切换、移动端长按、暗色模式和模型加载失败时的稳定性。

本次的“小姐姐”定义为精致的 Live2D 角色，不扩展为照片视频或 3D 真人系统。真人视频/VRM 属于后续独立方案。

## 2. 方案选择

### 方案 A：新版运行库 + 自定义 Svelte 右键菜单（采用）

使用 `l2d-widget` 负责 Live2D canvas、WebGL 生命周期和模型加载，继续由 `PetCompanion.svelte` 管理右键菜单、气泡、长按和模型资料。

优点：

- 保持当前博客交互习惯，不被库内置的悬浮菜单限制；
- `l2d-widget` 暴露 `switchModel`、`sleep`、`playMotion`、`playMotionByFile`、`setExpression` 等能力，动作扩展清晰；
- 自定义菜单可以继续沿用博客现有玻璃拟态、暗色模式和无障碍处理；
- `l2d-widget` 使用 MIT，长期维护和二次定制更合适。

代价：需要重写旧版初始化、事件绑定和气泡调用，并重新处理销毁清理。

### 方案 B：完全使用新版内置悬浮菜单

直接交给 `l2d-widget` 管理模型切换、休眠和菜单，仅追加少量动作按钮。

优点是迁移代码更少；缺点是菜单变成悬浮按钮，不符合本次右键入口要求，动作和模型资料也不容易做成统一的中文面板，因此不采用。

### 方案 C：改造成独立 Electron 桌宠

参考完整桌宠项目，增加透明窗口、语音和 AI。

该方案适合操作系统级桌宠，但超出当前静态博客范围，需要安装包、权限和独立运行时，不作为本次实现路径。

## 3. 运行库与组件架构

### 3.1 运行库迁移

- `package.json` 移除 `oh-my-live2d`，新增 `l2d-widget`；
- `PetCompanion.svelte` 使用 `createWidget()` 创建实例；
- 传入模型数组，每个模型保留 `path`、`scale` 和位置偏移配置；
- 设置 `menus: { items: [] }`，关闭库内置动作菜单，由组件接管右键菜单；
- 通过 `widget.l2d.getCanvas()` 获取 canvas，直接绑定 `contextmenu`、移动端长按和点击事件，不再轮询旧版 `#oml2d-stage`；
- 使用 `widget.switchModel(index)` 切换模型；
- 使用 `widget.sleep()` 隐藏模型并使用新版状态条唤醒；
- 组件销毁时调用并等待 `widget.destroy()`，同时移除窗口事件和长按计时器。

### 3.2 加载状态

组件保留当前的 manifest 异步加载流程：

1. 请求 `/pets/manifest.json`；
2. 校验 `pets` 为非空数组；
3. 将清单映射为 `l2d-widget` 的模型配置；
4. 创建 widget 并等待底层 `l2d` 的 `loaded` 事件；
5. 记录当前模型索引，并读取该模型动作/表情清单；
6. 绑定右键和长按事件。

manifest 加载失败或格式非法时，宠物功能静默关闭；单个模型资源失败时显示降级气泡，不影响页面主体。

## 4. 右键菜单与互动设计

### 4.1 入口

- 桌面端：右键点击 Live2D canvas；
- 移动端：长按 450ms；触摸移动或抬起会取消长按；
- 菜单外点击、Escape 键关闭菜单；
- 菜单位置始终限制在视口内，避免靠近边缘时被截断。

### 4.2 菜单结构

菜单以当前模型名为标题，包含两个区域：

**形象区域**

- 网格展示所有模型缩略图；
- 当前模型显示选中态；
- 点击缩略图立即切换，并显示“已切换到……”气泡。

**互动区域**

- `聊天`：从当前模型语录池显示一次气泡；
- `卖萌`：调用当前模型配置的卖萌动作；
- `撒娇`：调用当前模型配置的撒娇动作或表情；
- `跳舞/唱歌`：优先调用舞蹈动作，没有时使用模型配置的唱歌动作；
- `随机动作`：从当前模型可用的非 idle 动作中随机选择；
- `隐藏`：调用 `widget.sleep()`。

没有对应动作的模型不会伪造动作名：菜单会依据 manifest 配置展示该模型真正可用的语义动作；动作资源缺失时回退为随机动作或提示“这个形象暂时没有配置该动作”。

### 4.3 气泡

新版 `Widget` 不暴露旧版的即时 `tipsMessage()` 方法，因此关闭库内置循环气泡，改由 Svelte 管理一层轻量气泡：

- 气泡内容来自 manifest 的 `quotes` 和组件内置兜底句池；
- 动作触发时显示对应短句；
- 气泡自动消失，重复触发会重置计时器；
- 气泡使用与当前菜单一致的浅色/暗色主题；
- 在 `prefers-reduced-motion` 下关闭浮动动画，只保留淡入淡出。

## 5. manifest 与动作映射

现有模型字段保留：`id`、`name`、`model`、`scale`、`avatar`、`quotes`。新增可选 `actions` 字段，用语义 ID 映射到模型实际动作文件或动作组：

```json
{
	"id": "pio",
	"name": "少女·Pio",
	"model": "https://cdn.jsdelivr.net/npm/oml2d-models@0.7.0/models/Pio/model.json",
	"scale": 0.06,
	"avatar": "/pets/avatars/pio.webp",
	"actions": {
		"cute": { "label": "卖萌", "file": "motions/Touch Dere1.mtn" },
		"tease": { "label": "撒娇", "file": "motions/Touch Dere2.mtn" },
		"dance": { "label": "开心", "file": "motions/Success.mtn" },
		"sleep": { "label": "睡觉", "file": "motions/Sleeping.mtn" }
	}
}
```

运行时通过 `getMotions()` 校验文件是否存在，再用 `playMotionByFile()` 播放。对于 Cubism 3/6 模型，动作文件路径直接来自 `.model3.json` 的 motion 配置；必要时也支持 `{ "group": "Taphead", "index": 0 }` 形式。表情通过可选的 `expression` 字段调用 `setExpression()`，不存在时仅播放动作。

## 6. 缩略图方案

Pio 和静香不再使用当前的通用手绘 SVG。改为从同一 Live2D 模型渲染出透明背景的静态预览，裁剪为统一的竖向宠物卡片：

- 文件放在 `public/pets/avatars/`；
- 优先使用 WebP，保留 PNG 作为兼容兜底；
- 缩略图使用 `object-fit: contain`，保留头发、身体和服装轮廓；
- 卡片不使用圆形裁切，避免少女模型再次变成普通头像；
- 缩略图和模型主画布使用相同的模型来源，避免“菜单头像”和实际宠物不一致。

如果某个模型没有可授权的静态预览，则使用带角色色和模型名的占位卡，不生成与原模型不一致的 AI 人脸。

## 7. 错误边界与兼容性

| 场景 | 处理 |
|---|---|
| manifest 请求失败 | 控制台警告，宠物组件不渲染 |
| manifest 为空或字段非法 | 跳过宠物功能，不阻塞页面 |
| 模型加载失败 | 保留菜单状态，显示错误气泡；切换到下一个模型 |
| 动作文件不存在 | 记录警告，回退到可用随机动作 |
| WebGL 初始化失败 | 静默关闭宠物，页面正常使用 |
| localStorage 或浏览器权限受限 | 不持久化，不影响当前会话 |
| 页面切换/组件卸载 | 清理事件、计时器、widget 和 WebGL 资源 |
| 移动端长按 | 450ms 后打开，移动/抬起取消 |

## 8. 测试与验收

### 自动检查

- `pnpm check`
- `pnpm build`
- `pnpm test`

如新增动作解析纯函数，则为动作文件存在性、回退动作和 manifest 映射补充 `node:test` 单元测试。

### 手动验收

- 右键模型能打开菜单，菜单不被视口边缘截断；
- 手机模拟触摸长按能打开菜单，普通点击不会误触发；
- Pio、静香缩略图能看出完整 Live2D 角色，且与主模型一致；
- 切换猫、狐娘和少女模型后，菜单标题、缩略图选中态和动作列表同步；
- 卖萌、撒娇、开心/唱歌、睡觉、随机动作至少有一个模型能实际触发；
- 聊天气泡能显示，重复点击不会叠加计时器；
- 隐藏后状态条可以唤醒；
- 暗色模式、窄屏和 `prefers-reduced-motion` 下布局可用；
- 页面切换或热更新后不会重复出现多个 canvas 或事件监听器。

## 9. 范围外

- 真人照片、真人视频、VRM/3D 角色渲染；
- AI 对话、语音合成、屏幕截图分析；
- 后端存储和跨设备宠物数据同步；
- 新增未经授权的商业角色模型；
- 同时显示多个 Live2D 宠物。
