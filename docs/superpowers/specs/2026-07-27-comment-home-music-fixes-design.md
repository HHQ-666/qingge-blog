# 评论、首页一言与电台体验修复设计

**日期：** 2026-07-27  
**状态：** 已确认，待实现

## 目标

修复评论区在移动端首次进入时偶发的初始化错位，移除桌面首页重复的今日一言，放慢移动端打字机效果，并完善电台曲库与播放模式。

## 范围

本次覆盖以下用户反馈：

1. 评论系统加载动画与首次进入移动端的布局异常。
2. 电台中同一歌手出现多首歌的问题，并补充 80/90 年代经典歌曲。
3. 桌面端首页横幅与左侧栏重复显示今日一言。
4. 移动端首页今日一言打字机效果过快。
5. 电台的顺序播放、随机播放、单曲循环。

已迁移至 R2 的 CSDN 图片不在本次改动范围内。

## 设计

### 1. 评论区：单次加载、可重入挂载

`Comment.astro` 使用一个共享的 Twikoo 脚本加载 Promise，确保同一浏览会话中只插入和加载一次外部脚本。

每次页面进入时：

- 只对当前页面存在的评论宿主执行挂载；
- 使用挂载序号防止较早的异步回调覆盖较新的页面；
- 已挂载的宿主不重复调用 `twikoo.init`；
- 在等待期间显示项目自身的居中加载状态；
- 为 Twikoo 头像图片增加最大尺寸与 `object-fit` 约束，避免外部样式或资源延迟时把头像拉伸为整屏。

主题切换不再重复初始化评论区；评论组件保留当前内容，由其已有主题样式响应页面主题。

### 2. 首页今日一言

首页横幅中的今日一言仅在窄屏显示。组件 CSS 会明确在 `640px` 及以上隐藏它，避免本地 `display:flex` 规则覆盖 Tailwind 的 `sm:hidden`。

左侧栏的 `Hitokoto` 组件保持不变，继续作为桌面端唯一的今日一言入口。

移动端打字机间隔从 `42ms` 调整为约 `72ms`。当系统启用“减少动态效果”时，仍直接展示完整文本。

### 3. 电台曲库

采用“配置维护的精选曲库”方案：

- 保留当前可播放歌曲中的代表作；
- 配置中同一歌手只保留一首；
- 补充若干 80/90 年代华语经典歌曲；
- 每首新增歌曲先通过现有 Meting 接口验证为可播放后再写入配置；
- 使用已有曲目 ID 指纹缓存，曲库变更自动使旧缓存失效。

不使用播放时临时按歌手去重，也不依赖第三方动态歌单，保证播放顺序、内容和页面展示可预测。

### 4. 电台播放模式

播放器新增一个模式切换控件，依次切换：

- **顺序播放**：当前曲目结束后播放下一首，到末尾后回到第一首；
- **随机播放**：结束后从其他歌曲中随机选择一首；仅一首歌时仍播放该歌；
- **单曲循环**：结束后从头播放当前歌曲。

模式存入浏览器本地存储，在下次访问时恢复。上一首、下一首和迷你播放器继续可用；模式会统一影响所有播放入口和自动结束后的行为。

## 验收标准

- 移动端首次打开文章页时，评论区不会出现放大的默认头像、重叠输入项或歪斜的加载状态；刷新前后布局一致。
- 在客户端路由切换和主题切换后，单页中只有一个正常工作的评论区。
- 宽度大于等于 640px 的首页横幅不显示今日一言；左侧栏今日一言正常显示。
- 小于 640px 的首页横幅今日一言正常显示，打字机节奏明显放缓；减少动态效果时不逐字动画。
- 电台配置中每位歌手最多一首歌，新增曲目均可通过当前 API 获取播放信息。
- 模式按钮可在三种模式间循环切换，刷新页面后保持选择；歌曲播放结束时符合对应模式。
- 生产构建通过，桌面与移动尺寸下的首页、文章评论区、电台均完成手动验证。

## 非目标

- 不替换 Twikoo 服务端或评论数据。
- 不改动现有 R2 图片迁移、Worker 或域名配置。
- 不引入付费音乐接口，也不提供歌曲下载功能。
