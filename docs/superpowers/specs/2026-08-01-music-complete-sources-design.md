# Music Complete Sources Design

## Goal

让音乐播放器只展示并播放经过完整性验证的歌曲，同时从现有候选曲库中补充更多可验证的华语经典歌曲。

## Decision

采用运行时过滤与配置预筛选结合的方案。配置中的歌曲只作为候选元数据；播放器请求主音源和备用音源，并使用浏览器音频元数据确认实际时长不少于 90 秒。只有通过校验的歌曲进入列表、缓存和播放索引，试听片段、无 URL、音频加载失败的歌曲全部隐藏。

## Data flow

1. `src/config.ts` 提供歌曲标题、歌手和 ID 候选，最多保留 30 位不同歌手。
2. `fetchSong()` 按主 API、备用 API 顺序获取 URL。
3. `probeAudio()` 加载音频元数据，要求时长 `>= 90` 秒。
4. `getPlayableSongStates()` 只返回 `status === "ready"` 且有音源的状态。
5. 列表、播放索引和缓存都只消费通过校验的状态。

探测脚本用于从已有候选曲目中补充配置；最终运行时探测仍是权威校验，因为第三方接口的 URL 和权限可能变化。

## UI behavior

- 加载中只显示已经确认完整的歌曲，不显示“失败”“试听”“重试”行。
- 加载完成且有歌曲时显示“共 N 首完整音源”。
- 没有歌曲时显示“暂无完整音源”。
- 顺序、随机、单曲循环、媒体会话和 URL 失效恢复继续基于 ready 列表工作。

## Cache and failure handling

缓存版本升级到 v4，主动淘汰旧缓存。缓存读取时仍重新检查时长；失败歌曲不写入缓存，也不影响其他歌曲加载。备用 API 全部失败时，歌曲只在内部标记失败并从界面隐藏，下一次打开播放器会重新尝试。

## Verification

- 添加纯函数测试，确保只有 ready 状态进入可播放列表。
- 更新播放器源代码测试，确保不再渲染不完整音源提示行。
- 运行歌曲探测脚本并只补入通过验证的候选。
- 运行完整 Node 测试、`pnpm check` 和生产构建。
